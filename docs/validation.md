# 验证与限制

本机开发验证环境：macOS Apple Silicon、Zellij 0.45.1、Docker / OrbStack。没有升级或修改系统软件配置。

单元和安全测试覆盖密码初始化/变更/撤销、Host/Origin/CSRF、权限、目标校验、任务进程身份与生命周期、会话发现超时、普通命令解析、终端入口的同名防重复创建、旧 AI 路由已移除。

显式 live 测试创建自己的测试资源：

- 会话创建、重复进入复用、保存退出后恢复。
- 原生终端/控制 WebSocket，UTF-8 命令、双客户端、断开后任务保留和重连。
- 控制台的 Tab/Pane 查询和变更路由均返回 404，界面只有会话管理。
- 运行会话不允许用“删除历史”误删；“结束并删除”先停任务、备份归档、核验删除；重复删除幂等。

浏览器验证通过临时登录目录进行，后端系统与 Zellij 状态来自真实本机，不使用模拟运行状态；不会设置或覆盖用户密码。新建与恢复自动进入官方新标签页，无额外 Token 或控制台重复确认。

本机曾复现：已退出会话的无子任务残留进程继续重写归档，导致 CLI 显示删除成功后记录再次出现。修复增加退出残留的精确身份校验与清理，其他会话和程序保持运行。私有备份、进程输出和截图留在本机，不随代码发布。

尚未验收：Ubuntu 实机、实体手机上的各类中文输入法及软键盘、真实整机重启、公网 TLS/域名接入。浏览器弹窗和剪贴板权限受浏览器限制。Zellij 自身 IPC 异常会显示警告，不用模拟数据或静默重建现有会话掩盖问题。


## 黑屏检查记录

本机复现旧 dev-demo：WebSocket 握手正常，但直接连接原生 8082 也没有终端画面；同机新会话和 Codex 会话可以输出。重启 Web 接入服务没有恢复该旧会话。关闭自动 Ping 可消除不支持帧的日志，但 45 秒对照测试中有/无 Ping 两组都保持连接，不能将 Ping 断言为本次黑屏唯一原因。

经用户明确批准后，先保存布局和缓冲，再重建 dev-demo；损坏的旧服务未响应正常停止，核对原 PID/创建时间后结束该实例。原 Codex 服务未重启。恢复后的原生页面已实际显示并执行 printf 测试；恢复后的布局另按保存记录复核。通过真实 Uvicorn 网关空闲 45 秒，终端与控制两条连接仍 OPEN，持续收到原生消息；注销撤销连接而不停止会话。

该恢复证明当前旧会话已恢复可用，不表示已修复 Zellij 内部所有可能的附加故障。不得为了消除黑屏自动重建用户的现有会话；需要中断程序的恢复仍由用户批准。

## 局域网与私有组网入口

新增共享网络策略测试覆盖：可配置绑定地址、目标 IP/主机名白名单、错误端口/通配符/异常 Host 拒绝、同源校验、远端及映射回环的首次密码设置拒绝、HTTP 与 WebSocket 登录校验、HTTPS Cookie 标记。默认仍为 localhost；不同目标地址间不放宽跨源限制。

本机实际启用 IPv4 监听后，8765 的 localhost、局域网与一条现有组网映射入口均返回页面 200、未登录 API 401。另用临时隔离的密码目录和 8766 测试端口，通过真实局域网 IP 和同一条组网映射分别验证密码登录、官方终端页面、terminal/control 双 WebSocket、实际命令执行、断开后重新进入及注销；只创建和清理自有测试会话，原有会话 PID/创建时间保持不变。测试没有读取或更改用户密码。

另一条映射入口在本机自访问测试中建立 TCP 后未返回 HTTP；同一 Host 经本机直连的策略测试通过，不能仅凭此判定远端客户端的表现或组网故障原因。尚未取得另一台笔记本上的实际浏览器验收结果；没有改动组网映射、防火墙或路由配置。私有地址和本机 `.env` 不随源码提交。

## 文件、项目与开发环境增量

在既有 37 项测试基础上增加文件、项目、环境测试；当前单元/安全测试 51 项通过，显式本机 live 6 项通过。两个 Node 原生交互测试通过；新增覆盖文件名 HTML 转义、异步读取竞态、未保存编辑切页/刷新保护。Impeccable 机械检查未返回问题。

- 文件阶段：真实文件上传、重复上传拒绝、编辑及外部修改冲突、并发同名上传、Range 与 16 MiB 稀疏文件限制、目录复制/移动/删除、回收恢复、恢复目标冲突；路径穿越、软链接/硬链接、敏感子树、系统路径写入拒绝。临时 Uvicorn 服务另实测 5 MiB 分块上传与下载，SHA-256 一致，Range 和无覆盖均通过。
- 项目阶段：真实临时 Git 仓库初始化及提交后，验证状态、分支、提交、Diff、敏感文件排除、fsmonitor 禁用和 core.worktree 重定向拒绝；确认门禁与过期预设阻止，移除记录不删除文件。
- 环境阶段：被动读取虚拟环境元数据，未执行测试中的项目解释器；绑定与版本冲突校验；缺少确认/已有目录拒绝。实际用本机 Python 创建自有测试 venv，发现其版本与 pip 元数据；不自动绑定，也不覆盖已有目录。

浏览器使用隔离的认证/元数据目录，系统工具、Git、文件和 Zellij 皆来自本机真实能力。测试项目是本轮新建的专用 QA 目录，不冒充用户已有项目。实际验证中文编辑、目录添加项目、Git Diff、确认后运行 npm 预设且既有任务页输出验收标记、venv 创建及绑定、依赖查看、Homebrew 查询、回收恢复。后端重启后，项目/环境关联仍可读取。文件页启动的原生新会话显示所选 QA 工作目录，不再次输入 Token；已有会话目录保留的行为另由 live 测试覆盖。检查浅/暗主题及窄视口布局，没有页面级水平溢出，浏览器没有捕获 JS error。

本机控制台更新后，localhost、局域网和已通的组网入口页面为 200，新增文件 API 未认证返回 401。比对更新前后原有 Zellij 服务 PID/创建时间、运行容器 ID/启动时间/PID 和任务定义，均未改变。测试凭据、目录、虚拟环境和会话与用户资源隔离，验收后清理自建资源，不导入模拟项目到生产元数据。

未验收：实体手机软键盘和各类浏览器、异地笔记本完整新模块交互、数 GiB 实际传输、NAS/断网文件系统、Ubuntu 整机部署与 APT 实机操作。Git 仓库检查不是对项目代码的安全审计；同账户本机写入者不受 Web 路径锁沙箱化约束，外部持续写文件也没有事务快照保障。文本原子替换保留普通权限位，未承诺保留所有 ACL/扩展属性。环境和预设任务的支持范围详见 README。

## DSH 0.2.2 与顶栏

实际检查 DMG 的 Info.plist 与附带 CLI，版本均为 0.2.2-rc.1；用户执行 npx 后 npm 缓存也为同版本。初期发现的 0.1.0-rc.6 旧实例仅用于兼容探查，已清理自建实例，最终版本拒绝选择 0.1 旧缓存。桌面版使用独立 Desktop profile/Host，控制台使用官方 Web profile，二者不假定共享运行中的任务。

新增 8 项 DSH 测试，完整单元/安全测试当前 59 项通过，live 6 项通过，并保持使用自有资源（原先绑定 codex-agent 的测试已改为自建会话），两个 Node 界面测试通过。覆盖 HTTP/WS 登录、严格同源、注销撤销、每帧复核、凭据隔离、端口分发、旧版拒绝、启动复用和 Token 日志遮盖。原生认证从启动 URL 调用官方流程完成，上游 Cookie/Token 留在 0600 文件。DSH 插件 bundle 经网关与本机原始内容 SHA-256 一致；HTML 仅增加标准 randomUUID 缺失能力补丁。

隔离 RemoteHub 测试凭据下，实际通过局域网浏览器加载嵌入的原生 DSH 0.2.2 页面，以及独立窗口中的工作区目录浏览、原生权限/模型菜单和中文编辑（测试文字已清空，未发送模型请求）。嵌入框的画面和真实模型/权限状态可读取，但自动化工具对跨 Origin iframe 的点击返回目标失效，原生交互验证通过独立窗口完成。窄屏检查无页面级横向溢出；顶栏太阳/月亮按钮与修改密码入口可用，密码对话框仅打开后取消，未改用户密码。DSH 自己的主题由它的原生设置控制。

最终部署使用 8765 控制台、8767 认证网关、9741 本机原始 Host。localhost、192.168.31.160 与 100.66.1.4 均实际验证页面、认证 native mux、注销后 401 和 socket 关闭。组网路径在中间测试中观察到客户端关闭延迟，最终调整关闭顺序和逐帧校验后重测通过。测试从本机发往现有组网映射，不替代异地实体笔记本验收。

部署前后核验已有 Zellij PID/创建时间、Docker 容器 ID/启动时间/PID、后台任务定义及受管 DSH Host PID，均保持一致。桌面版进程保持运行。控制台停止/启动后原生 Host 与工作区可复用。没有验证真实模型流式输出、付费推理、任务中断/审批完成闭环、所有第三方插件、桌面专用功能、OAuth、真实整机重启或实体手机 IME。当前浏览器测试产生的原生空白新会话属于官方客户端初始化行为，未提交模型输入。
