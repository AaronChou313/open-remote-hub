## 分组节点交互与 macOS DNS 修正（2026-11-10）

用户首次手动切换后报告 Codex 断连，并已自行停用新 TUN、恢复 Clash。排查发现旧配置漏设 `tun.dns-mode`，macOS 的默认行为为不接管系统 DNS；向局域网 DNS 查询 chatgpt.com / api.openai.com 返回异常地址，而本机 Mihomo DNS 返回 Fake-IP。另一个独立问题是规则模式的默认策略组与 GLOBAL 不同：选中 GLOBAL 的 AI 节点没有改变规则模式的机场主策略组。界面现在展示默认路由链，并明确 GLOBAL 的作用范围。

修正为 `dns-mode: native`，由内核随 TUN 启停接管/恢复系统 DNS。真实隔离内核的配置检查及 GET /configs 均确认该字段生效且 TUN 关闭。用户已授权更新 root-owned 服务，运行副本哈希与源码一致，network_revision=2，保留机场配置与选中状态。修正后的独立 TUN / 系统 DNS / Codex 连通性仍须用户再次手动切换验收，本轮没有自行启用 TUN。

节点页改为可折叠分组与节点按钮，支持默认/名称/延迟排序、搜索、单节点/整组/全部测速与取消。批量按名称去重，跳过内置动作，最多 4 个并发；代理 broker 允许只读请求并发。真实浏览器完成单节点、10 节点分组、62 节点全部测速及取消，显示实际延迟与未连通结果；这些测量在 Clash 保持开启时进行，不能据此宣称新 TUN 独立工作正常。

真实隔离 Mihomo + FastAPI 认证接口完成包含斜线/中文组名的节点切换和模式切换，不传确认字段，不接管网络。单元/交互测试覆盖自动组固定与恢复、配置变更拒绝旧点击、登出取消剩余测速、折叠排序持久化、单击切换不弹确认。文件保存、文件重命名/移动、环境绑定和代理普通操作移除重复弹窗，保留版本核验、鉴权、破坏性操作与未保存内容保护。
