# 验证与限制

本机开发验证环境：macOS Apple Silicon、Zellij 0.45.1、Docker / OrbStack。没有升级或修改系统软件配置。

单元和安全测试覆盖密码初始化/变更/撤销、Host/Origin/CSRF、权限、目标校验、任务进程身份与生命周期、会话发现超时、普通命令解析、终端入口的同名防重复创建、旧 AI 路由已移除。

显式 live 测试创建自己的测试资源：

- 会话创建、重复进入复用、保存退出后恢复。
- 原生终端/控制 WebSocket，UTF-8 命令、双客户端、断开后任务保留和重连。
- 控制台的 Tab/Pane 查询和变更路由均返回 404，界面只有会话管理。
- 运行会话不允许用“删除历史”误删；“结束并删除”先停任务、备份归档、核验删除；重复删除幂等。

浏览器验证通过临时登录目录进行，后端系统与 Zellij 状态来自真实本机，不使用模拟运行状态；不会设置或覆盖用户密码。新建与恢复自动进入官方新标签页，无额外 Token 或控制台重复确认。

本机曾复现：已退出会话的无子任务残留进程继续重写归档，导致 CLI 显示删除成功后记录再次出现。修复增加退出残留的精确身份校验与清理，其他会话和程序保持运行。私有备份、进程输出和截图留在本机，不随代码发布。

尚未验收：Ubuntu 实机、实体手机上的各类中文输入法及软键盘、真实整机重启、公网 TLS/域名接入。浏览器弹窗和剪贴板权限受浏览器限制。Zellij 自身 IPC 异常会显示警告，不用模拟数据或静默重建现有会话掩盖问题。


## 黑屏检查记录

本机复现旧 dev-demo：WebSocket 握手正常，但直接连接原生 8082 也没有终端画面；同机新会话和 Codex 会话可以输出。重启 Web 接入服务没有恢复该旧会话。关闭自动 Ping 可消除不支持帧的日志，但 45 秒对照测试中有/无 Ping 两组都保持连接，不能将 Ping 断言为本次黑屏唯一原因。

经用户明确批准后，先保存布局和缓冲，再重建 dev-demo；损坏的旧服务未响应正常停止，核对原 PID/创建时间后结束该实例。原 Codex 服务未重启。恢复后的原生页面已实际显示并执行 printf 测试；恢复后的布局另按保存记录复核。通过真实 Uvicorn 网关空闲 45 秒，终端与控制两条连接仍 OPEN，持续收到原生消息；注销撤销连接而不停止会话。

该恢复证明当前旧会话已恢复可用，不表示已修复 Zellij 内部所有可能的附加故障。不得为了消除黑屏自动重建用户的现有会话；需要中断程序的恢复仍由用户批准。
